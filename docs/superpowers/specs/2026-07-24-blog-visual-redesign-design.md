# Farice Blog 全站视觉升级设计

## 目标

在不改变现有 Jekyll 内容模型、文章 URL、分类标签数据和 Giscus 评论系统的前提下，对博客进行完整的视觉与交互升级。

最终方向由视觉评审确定：

- 视觉风格：渐变玻璃。
- 首页布局：瀑布卡片墙。
- 文章布局：粘性目录与双栏正文。
- 主题策略：默认跟随操作系统，提供手动切换并记住用户选择。
- 页面范围：首页、文章、归档、分类、标签、合集、关于和 404 页面全部统一。

## 当前问题

- 首页仍使用线性列表与传统左右浮动布局，信息层级弱。
- 导航、页脚和侧边栏使用深灰旧式视觉，与新评论组件缺少统一性。
- `_sass` 中存在多套历史样式，颜色、宽度、阴影和断点分散硬编码。
- 桌面端目录依赖 JavaScript 计算固定宽度与页面底部距离，维护成本高。
- 移动端目录通过缩放弹层实现，交互与可访问性较弱。
- 页面标题、按钮和导航混合中英文，品牌表达不统一。
- 深色模式、主题偏好保存、减少动画偏好和清晰焦点状态均缺失。
- 首页、文章页、归档、分类和标签页面分别维护相似结构，重复代码较多。
- `404.md` 没有 Front Matter，无法进入统一布局。

## 设计原则

1. **内容优先**：视觉服务于技术文章发现和长文阅读，不牺牲正文可读性。
2. **统一令牌**：颜色、间距、圆角、阴影、字体和容器宽度由 CSS 自定义属性统一管理。
3. **渐进增强**：无 JavaScript 时内容、导航和目录仍可访问；JavaScript 只增强主题、菜单和阅读进度。
4. **响应式优先**：使用 CSS Grid、Flexbox、`clamp()` 和媒体查询，不通过脚本计算布局宽度。
5. **低依赖**：优先使用浏览器原生能力，避免增加前端框架和运行时依赖。
6. **保持兼容**：保留现有文章、Front Matter、永久链接、分页和评论映射。

## 视觉系统

### 颜色

浅色主题：

- 页面底色使用低饱和冷灰蓝。
- 品牌渐变使用紫色到青色。
- 主要文本使用深蓝黑，次要文本使用中性蓝灰。
- 卡片使用半透明白色与柔和边框，实现克制的玻璃质感。

深色主题：

- 页面底色使用深蓝黑，不使用纯黑。
- 卡片使用半透明深蓝灰。
- 品牌渐变保留紫青色，但降低高光面积。
- 正文文本保持足够对比度，代码块与引用使用独立层级。

颜色通过 `[data-theme="light"]`、`[data-theme="dark"]` 和系统偏好媒体查询映射到同一组语义变量，例如：

- `--color-bg`
- `--color-surface`
- `--color-surface-strong`
- `--color-text`
- `--color-muted`
- `--color-border`
- `--color-primary`
- `--color-accent`
- `--gradient-brand`

### 字体

- 导航、标题、元数据和 UI 使用系统无衬线字体栈。
- 中文正文优先使用系统可用的中文衬线字体，并提供无衬线回退。
- 代码使用系统等宽字体栈。
- 不下载第三方 Web Font，避免额外网络请求和字体闪烁。

### 空间与形状

- 页面内容最大宽度约 1200–1280px。
- 正文阅读宽度控制在约 680–760px。
- 卡片圆角统一为中等偏大尺寸。
- 阴影只用于导航、重点卡片和悬浮控件，不让所有元素都产生重阴影。
- 页面区块使用稳定的垂直节奏，并通过 `clamp()` 适应屏幕宽度。

## 全局框架

### 页面背景

页面使用冷色基础背景和两个低透明度径向渐变光斑。渐变固定在视觉层，不阻塞交互，也不创建大型图片资源。

### 导航栏

导航栏使用半透明玻璃容器，位于页面顶部并在滚动后保持可见。

桌面端包含：

- Farice 品牌入口。
- 首页、文章/归档、分类、标签、关于入口。
- 当前页面状态。
- 主题切换按钮。

移动端：

- 保留品牌与主题按钮。
- 使用明确的菜单按钮展开导航。
- 支持 Escape 关闭、点击外部关闭和正确的 `aria-expanded` 状态。

### 页脚

页脚改为轻量玻璃卡片，不再使用全宽深灰色块。保留站点说明、GitHub、邮箱、访问统计和 Jekyll/GitHub Pages 说明，并减少重复文本。

### 返回顶部与阅读进度

- 返回顶部按钮使用固定圆形玻璃按钮，滚动到阈值后显示。
- 文章页顶部显示细阅读进度条。
- 支持 `prefers-reduced-motion: reduce`，关闭非必要过渡和滚动动画。

## 首页

### 品牌首屏

首页顶部使用紫青渐变 Hero：

- 标题表达技术探索与工程实践。
- 简短说明覆盖 AI、云原生和软件工程主题。
- 提供“浏览文章”和“关于我”两个入口。

### 瀑布卡片墙

文章使用 CSS Grid 组成响应式卡片墙：

- 当前分页的第一篇文章作为重点卡片，占用更大网格面积。
- 其余文章根据顺序使用普通或横向卡片变化。
- 每张卡片显示分类、标题、摘要、发布日期、预计阅读时间和标签。
- 卡片背景由渐变与装饰图形构成，不要求文章提供封面图。
- 整张卡片可点击，同时保留清晰的键盘焦点状态。

桌面端使用多列网格；平板端减少列数；移动端切换为单列，重点卡片不再跨行。

### 分页

分页使用清晰的上一页、页码状态和下一页按钮，修复当前末页地址拼接逻辑。禁用状态不可聚焦并具有明确视觉区分。

### 首页侧边信息

移除传统右侧 Recent Posts/Categories/Tags 侧栏，将内容整合为卡片墙下方的主题导航区：

- 热门分类。
- 标签云。
- 归档入口。

这样避免首页在中等屏幕上出现狭窄双栏。

## 文章详情页

### 文章头部

文章头部显示：

- 分类或主标签。
- 标题与可选摘要。
- 作者、发布日期和预计阅读时间。
- 标签列表。

标题区域保持明亮简洁，不使用占据过多首屏高度的大封面。

### 双栏阅读布局

桌面端使用：

- 左侧粘性目录。
- 右侧正文内容。

目录使用 CSS `position: sticky`，不再通过 JavaScript计算宽度、页脚距离或固定状态。当前章节可由轻量 JavaScript 与 IntersectionObserver 高亮。

移动端：

- 正文改为单列。
- 目录变为文章头部下方的可折叠区域。
- 目录展开状态具有可访问按钮与键盘支持。

### 正文排版

- 中文正文使用舒适的行高和受控行宽。
- `h2`–`h6` 具有稳定层级和滚动定位间距。
- 链接使用品牌色与下划线反馈，不再通过大面积背景色表示悬停。
- 图片自适应宽度并具有统一圆角。
- 表格支持横向滚动。
- 引用、提示块、列表、代码块和行内代码统一视觉。
- 代码块保留 Rouge 高亮，但改为与深浅主题协调的颜色。

### 文章辅助区

- 上一篇/下一篇使用两张导航卡片。
- 相关文章改为紧凑卡片列表。
- Giscus 评论区沿用现有配置，并跟随当前手动主题切换。

## 内容索引页

### 归档

- 使用年份时间线布局。
- 每年显示文章数量。
- 桌面端年份导航粘性显示；移动端自然流式排列。

### 分类

- 页面顶部显示分类概览卡片与数量。
- 下方按分类展示文章列表。
- 分类锚点保持现有 URL 行为。

### 标签

- 标签顶部使用可点击标签云。
- 下方按标签显示文章列表。
- 标签名称、计数和锚点使用统一样式。

### 合集与关于

- 继续使用 Markdown 内容。
- 通用页面布局提供标题、简介、正文卡片和可选粘性目录。
- About 页面联系信息使用清晰的链接卡片，不改变现有个人内容含义。

### 404

- 增加 Front Matter 并使用默认布局。
- 显示友好说明、返回首页按钮和查看归档入口。
- 不引入搜索后端。

## 主题系统

主题决策顺序：

1. 如果本地保存了用户选择，使用 `light` 或 `dark`。
2. 否则跟随 `prefers-color-scheme`。
3. 系统主题变化时，仅在用户没有手动覆盖时自动更新。

主题脚本在页面绘制前设置根元素属性，避免明显闪烁。导航按钮允许手动切换，并通过 `localStorage` 保存选择。

主题切换还需要同步更新：

- 浏览器 `theme-color`。
- Giscus 评论 iframe。
- 按钮的图标、标题和无障碍标签。

## JavaScript 设计

将现有脚本拆分为明确的增强模块：

- `theme.js`：主题初始化、切换、系统偏好监听和 Giscus 同步。
- `navigation.js`：移动菜单开关和点击外部关闭。
- `article.js`：阅读进度、目录折叠与当前章节高亮。
- `main.js`：返回顶部等全局轻量行为；或作为小型入口协调上述模块。

脚本必须：

- 在目标元素不存在时安全退出。
- 不覆盖全局 `window.onscroll`。
- 使用 `addEventListener`。
- 不依赖 jQuery。
- 不通过 JavaScript 设置布局宽度。

如果现有 Jekyll/GitHub Pages 构建不支持模块脚本，则使用多个普通 `defer` 脚本，并保持每个文件职责独立。

## Sass 组织

保留 `css/main.scss` 作为唯一入口，并将新样式按职责拆分：

- `_sass/_tokens.scss`：设计令牌与主题变量。
- `_sass/_base.scss`：重置、字体、背景和通用元素。
- `_sass/_header.scss`：导航与主题按钮。
- `_sass/_home.scss`：Hero、卡片墙、主题导航和分页。
- `_sass/_post.scss`：文章头部、正文、目录、相关文章和评论。
- `_sass/_content-index.scss`：归档、分类和标签。
- `_sass/_page.scss`：合集、关于和 404。
- `_sass/_footer.scss`：页脚。
- `_sass/_utilities.scss`：可访问隐藏、容器和少量通用辅助类。

不继续扩展未被 `css/main.scss` 引用的历史 `_layout.scss`。旧样式在对应新组件稳定后删除，避免新旧规则叠加。

## 性能

- 不增加前端框架、图标包或 Web Font。
- 使用 CSS 渐变代替大幅背景图片。
- 移除可由原生 `scroll-behavior` 替代的旧平滑滚动脚本。
- 所有交互脚本使用 `defer`，评论继续懒加载。
- 内容图片添加响应式尺寸规则；现有文章内容不批量重写。
- 保持首次可见内容无需等待 JavaScript。

## 可访问性

- 所有按钮具有文本或 `aria-label`。
- 菜单、主题和目录按钮维护 `aria-expanded` 或当前状态。
- 键盘焦点清晰可见。
- 文本与背景满足可读对比度。
- 动效尊重减少动画偏好。
- 主内容、导航、页脚使用语义元素。
- 页面只有一个主要 `h1`，标题层级连续。
- 装饰渐变与图形不被辅助技术朗读。

## 内容与兼容性

必须保持：

- 所有现有文章和草稿内容。
- 现有永久链接结构。
- 分类、标签、归档和分页数据。
- RSS feed。
- Giscus `pathname` 评论映射。
- 现有 Google/Baidu 统计配置开关。
- GitHub Pages 可使用的 Jekyll/Liquid 语法。

可统一调整页面显示文案，但不修改文章正文含义。

## 测试策略

继续使用依赖无关的 Python `unittest` 静态回归测试，并在实现过程中扩展覆盖：

1. 设计令牌和深浅主题变量存在。
2. 主题脚本遵循本地偏好优先、系统偏好回退。
3. 首页 Hero、卡片网格与分页结构存在。
4. 文章页粘性目录、阅读进度、移动目录和 Giscus 区域存在。
5. 归档、分类、标签、About 和 404 使用统一布局类。
6. 移动菜单与主题按钮具有必要无障碍属性。
7. 不再引用旧 `scroll.min.js` 或依赖布局计算的旧目录代码。
8. 无硬编码凭据或不安全可配置脚本地址。

如果本地 Jekyll 工具链可用，执行完整构建。若不可用，至少执行：

- Python 回归测试。
- YAML 解析。
- JavaScript 语法检查。
- `git diff --check`。
- 旧选择器和脚本引用扫描。

## 实施阶段

1. 建立设计令牌、主题初始化和全局页面框架。
2. 重构导航、移动菜单、页脚和全局控件。
3. 重构首页 Hero、瀑布卡片墙、主题导航和分页。
4. 重构文章头部、双栏正文、粘性目录、阅读进度和辅助区。
5. 统一归档、分类、标签、合集、关于和 404 页面。
6. 删除失效旧样式与旧布局脚本。
7. 完成深浅主题、移动端和可访问性验证。

## 非目标

本次不实现：

- CMS 或在线文章编辑器。
- 站内全文搜索后端。
- 用户账户系统。
- 自定义图片上传或 CDN 管理。
- React、Vue 或其他前端框架迁移。
- 全量重写历史文章内容。
- 评论计数、点赞统计或推荐算法。

## 验收标准

- 最终页面与确认的渐变玻璃方向一致。
- 首页使用响应式瀑布卡片墙，重点文章具有明确层级。
- 文章桌面端使用粘性目录双栏布局，移动端为单列折叠目录。
- 全站默认跟随系统主题，并支持记忆手动选择。
- 首页、文章、归档、分类、标签、合集、关于和 404 页面视觉统一。
- 所有现有 URL、文章内容、分页和 Giscus 评论映射保持可用。
- 页面在 360px 移动屏幕上无横向溢出。
- 键盘可操作导航、主题按钮和目录。
- 减少动画偏好得到尊重。
- 新增回归测试通过；可用的构建与语法检查通过。
